# MakanApa? Documentation

Read these documents in this order before continuing development:

1. [`PROJECT_OVERVIEW.md`](PROJECT_OVERVIEW.md) — why the application exists and its product philosophy.
2. [`CURRENT_STATE.md`](CURRENT_STATE.md) — exact hand-off point from the latest completed development phase.
3. [`ARCHITECTURE.md`](ARCHITECTURE.md) — application/Docker boundaries and responsibilities.
4. [`DEVELOPMENT_WORKFLOW.md`](DEVELOPMENT_WORKFLOW.md) — how development should be performed.
5. [`AI_AGENT_GUIDELINES.md`](AI_AGENT_GUIDELINES.md) — rules for AI-assisted implementation.
6. [`ROADMAP.md`](ROADMAP.md) — intentionally unimplemented future work.
7. [`DECISIONS.md`](DECISIONS.md) — decisions that should not be casually reversed.

## Documentation Maintenance

Whenever a feature materially changes the system, update the relevant docs in the same change.

`CURRENT_STATE.md` should describe what exists **now**.

`ROADMAP.md` should describe what might be built **later**.

Do not mix the two.
